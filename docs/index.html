Build an XGS image

An OPNsense image for a Sophos XGS appliance, with the os-xgs-npu driver and plugin already in it. Pick the options, and this page opens a build request for you.

1Pick the optionsYou are here. Nothing has started yet.
2Submit the issueGitHub asks you to confirm. Nothing runs until you do.
3Download the imageFrom the run's artifacts, for seven days.
This image has not been booted on any appliance. Burn one and boot it before relying on it. The build runs on a GitHub runner, which has no Sophos hardware attached to it and never will. Nothing on this page has been tested on a device.
You are looking at the original repository's page. A build only runs for the account that owns the repository, so pressing the button here will file an issue that the workflow politely declines. To build one for yourself: fork the repository, turn on Pages for your fork (Settings, then Pages, branch main, folder /docs), and use your fork's copy of this page. That is the licence position, and the reason for it is in CONTRIBUTING.md: your build, your artifact, your storage.
The image what gets written to the disk

The official image is downloaded from OPNsense's own mirror at build time and its checksum is verified. No part of it lives in this repository.

The console the one choice that locks you out if it is wrong

An XGS appliance has no screen, so the serial port is the only way in. If this is wrong the appliance boots perfectly into a console you cannot read. Neither value is safer than the other in the abstract: match whatever your terminal is set to.

On an appliance with no video output the two behave the same way. Leave it on serial only unless you have a reason.

The driver fetched at build time, not stored here

Leave this as main unless you know why not. The source is placed in the image; no built module is, because a module has to be built against the kernel the appliance is actually running.
